# News Alpha Radar — 패치 변경 이력 & 안전 롤백 대장 (`PATCH_LOG`)

이 문서는 매매 전략·필터·리포트 코드의 **모든 변경 내역을 버전(Tag)·커밋 단위로 추적**하고, 실전 모의매매 성과가 기대에 못 미칠 때 **안전하고 빠르게 원복(Rollback)**하기 위한 공식 관리 대장입니다.

- **일별 수익 성적표 연동**: 비공개 로그 저장소 `jjangna0817-hue/news-alpha-radar-logs`의 `PATCH_HISTORY.md` 및 `reports/YYYY-MM-DD.md`(`## 5. 버전(commit)별 누적 성적 비교`)와 1:1로 대조합니다.

---

## 안전 롤백 원칙 (필독)

> **주의**: 우분투 서버의 `deploy/ubuntu/update.sh`는 2분마다 `git pull --ff-only origin main`을 실행합니다.
> 따라서 **`main` 브랜치에 `git reset --hard`나 force-push를 절대 하면 안 됩니다.** (서버 자동 업데이트가 중단됩니다.)

### 방법 A. 즉시 0초 롤백 (코드 수정 없이 대시보드 / `.env`에서 비활성화)
전략 수치 변경은 모두 대시보드 `[모의 자동매매]` 탭 또는 `.env`에서 즉시 원복할 수 있습니다.

### 방법 B. 코드 단위 롤백 (`git revert` — 서버 2분 내 자동 복구)
잘못된 패치 커밋을 되돌리는 **새 정방향 커밋**을 `main`에 반영합니다.

```bash
# 1) 특정 기능 1개만 되돌리기 (권장 — Rebase/Merge 커밋 유지 시)
git checkout main && git pull --ff-only origin main
git checkout -b revert/undo-feature
git revert <커밋_SHA>
git push -u origin revert/undo-feature
# 이후 GitHub PR 머지 → 2분 내 우분투 서버 자동 원복

# 2) 특정 패치 PR 전체를 통째로 되돌리기 (Merge commit이면 -m 1 추가)
git revert <머지_커밋_SHA>
```

> **PR 머지 팁**: 패치 PR을 머지할 때 **`Rebase and merge`**(또는 **`Create a merge commit`**)를 선택하면 아래 기능별 분리 커밋이 `main`에 그대로 남아 **원하는 기능 1개만 골라 `git revert`**할 수 있습니다. (`Squash and merge`를 선택하면 PR 전체 단위로만 `git revert` 가능하며, 대신 방법 A의 대시보드 토글로 개별 해제할 수 있습니다.)
